### What's new?

- **Run and connect AgentApps across a federation** ([#8143](https://github.com/flwrlabs/flower/pull/8143), [#8150](https://github.com/flwrlabs/flower/pull/8150), [#8166](https://github.com/flwrlabs/flower/pull/8166), [#8170](https://github.com/flwrlabs/flower/pull/8170), [#8175](https://github.com/flwrlabs/flower/pull/8175), [#8181](https://github.com/flwrlabs/flower/pull/8181), [#8183](https://github.com/flwrlabs/flower/pull/8183), [#8185](https://github.com/flwrlabs/flower/pull/8185), [#8192](https://github.com/flwrlabs/flower/pull/8192), [#8193](https://github.com/flwrlabs/flower/pull/8193), [#8197](https://github.com/flwrlabs/flower/pull/8197), [#8200](https://github.com/flwrlabs/flower/pull/8200), [#8204](https://github.com/flwrlabs/flower/pull/8204), [#8205](https://github.com/flwrlabs/flower/pull/8205), [#8209](https://github.com/flwrlabs/flower/pull/8209), [#8211](https://github.com/flwrlabs/flower/pull/8211), [#8214](https://github.com/flwrlabs/flower/pull/8214), [#8219](https://github.com/flwrlabs/flower/pull/8219))

  AgentApps can now run on both SuperLink and SuperNodes within a federation, enabling agents at the federation level and on individual nodes to communicate with one another. An AgentApp on SuperLink can discover available SuperNodes, send JSON messages to agents on selected nodes, and collect their replies; agents on SuperNodes can receive those messages and respond to the sender. The grid tools for agents expose this workflow through `get_nodes`, `push_messages`, and `pull_messages`. SuperNode-hosted AgentApps also support the Open Responses-compatible endpoint, user prompts, and run-series events.

- **Use Endeavor with ChatGPT/Codex and OpenCode** ([#8117](https://github.com/flwrlabs/flower/pull/8117), [#8199](https://github.com/flwrlabs/flower/pull/8199), [#8202](https://github.com/flwrlabs/flower/pull/8202))

  New guides explain how to connect ChatGPT/Codex and OpenCode to Endeavor. The documentation also distinguishes the supplied Codex configuration's 128,000-token context window and 96,000-token compaction threshold from the model's one-million-token maximum context length, while noting that effective request limits depend on the deployment and provider route.

- **Use native connector actions and access local files** ([#8164](https://github.com/flwrlabs/flower/pull/8164), [#8177](https://github.com/flwrlabs/flower/pull/8177), [#8178](https://github.com/flwrlabs/flower/pull/8178), [#8182](https://github.com/flwrlabs/flower/pull/8182), [#8191](https://github.com/flwrlabs/flower/pull/8191), [#8203](https://github.com/flwrlabs/flower/pull/8203))

  GitHub, Slack, and Notion connector actions now follow their native API names, options, responses, and diagnostics, while Attio's `identify` action matches its documented scopes. A new read-only filesystem connector provides `filesystem_list_directory` and `filesystem_read_file` within paths configured through `FLWR_FILESYSTEM_ALLOWED_DIRS`.

- **Name and locate registered SuperNodes** ([#8213](https://github.com/flwrlabs/flower/pull/8213), [#8215](https://github.com/flwrlabs/flower/pull/8215), [#8217](https://github.com/flwrlabs/flower/pull/8217), [#8218](https://github.com/flwrlabs/flower/pull/8218))

  Register a SuperNode with an optional human-readable `--name` and `--location <latitude>,<longitude>`. These values are persisted and exposed through `NodeInfo`, and `Grid.get_nodes()` gives applications access to the full node records.

- **View app metadata and federation associations** ([#8130](https://github.com/flwrlabs/flower/pull/8130), [#8195](https://github.com/flwrlabs/flower/pull/8195), [#8196](https://github.com/flwrlabs/flower/pull/8196))

  `ListApps` now includes Hub display names, colors, and descriptions. The new `ListAppAssociations` Control API reports the accessible federations associated with an app, including every accessible federation for the built-in Flower Agent.

- **Prepare faster Agent responses by prestarting `flwr-model` workers** ([#8187](https://github.com/flwrlabs/flower/pull/8187), [#8188](https://github.com/flwrlabs/flower/pull/8188))

  A single-use worker preloads the `flwr-model` task code before a task arrives, reducing startup work before an Agent response's first token. This lays the groundwork for lower time to first token (TTFT) once warm workers are integrated with Kubernetes.

- **Configure SuperExec without `--plugin-type`** ([#8151](https://github.com/flwrlabs/flower/pull/8151), [#8152](https://github.com/flwrlabs/flower/pull/8152), [#8153](https://github.com/flwrlabs/flower/pull/8153), [#8157](https://github.com/flwrlabs/flower/pull/8157))

  `flower-superexec` now selects the process to launch from the task type, so `--plugin-type` is deprecated, has no effect, and is no longer used in the documentation or Docker configuration. The obsolete `ServerappEphemeral` plugin has also been removed.

- **General improvements** ([#8145](https://github.com/flwrlabs/flower/pull/8145), [#8146](https://github.com/flwrlabs/flower/pull/8146), [#8156](https://github.com/flwrlabs/flower/pull/8156), [#8160](https://github.com/flwrlabs/flower/pull/8160), [#8161](https://github.com/flwrlabs/flower/pull/8161), [#8163](https://github.com/flwrlabs/flower/pull/8163), [#8165](https://github.com/flwrlabs/flower/pull/8165), [#8169](https://github.com/flwrlabs/flower/pull/8169), [#8171](https://github.com/flwrlabs/flower/pull/8171), [#8172](https://github.com/flwrlabs/flower/pull/8172), [#8174](https://github.com/flwrlabs/flower/pull/8174), [#8179](https://github.com/flwrlabs/flower/pull/8179), [#8198](https://github.com/flwrlabs/flower/pull/8198), [#8220](https://github.com/flwrlabs/flower/pull/8220))

  As always, many parts of the Flower framework and quality infrastructure were improved and updated.
