### What's new?

- **Start AgentApp and Connector tasks faster in warm Pods** ([#8225](https://github.com/flwrlabs/flower/pull/8225), [#8226](https://github.com/flwrlabs/flower/pull/8226), [#8227](https://github.com/flwrlabs/flower/pull/8227), [#8231](https://github.com/flwrlabs/flower/pull/8231), [#8232](https://github.com/flwrlabs/flower/pull/8232), [#8233](https://github.com/flwrlabs/flower/pull/8233))

  Kubernetes warm Pods can now preload single-use AgentApp and Connector workers before task dispatch, avoiding process startup and, for AgentApps, archive installation and import work on the task path. Exact-FAB AgentApp pools route matching tasks to the preloaded app while preserving generic warm-pool and cold fallbacks.

- **Use connectors in shared federations** ([#8210](https://github.com/flwrlabs/flower/pull/8210), [#8237](https://github.com/flwrlabs/flower/pull/8237), [#8239](https://github.com/flwrlabs/flower/pull/8239))

  Connector storage, OAuth sessions, APIs, and task metadata now carry federation scope, allowing members to connect, list, disconnect, and use connector-backed runs in shared federations. Existing credentials are preserved during migration, while pending OAuth sessions are cleared and multiple connections to the same provider remain unsupported.

- **Read Notion users, pages, properties, blocks, and meeting notes** ([#8245](https://github.com/flwrlabs/flower/pull/8245), [#8252](https://github.com/flwrlabs/flower/pull/8252), [#8255](https://github.com/flwrlabs/flower/pull/8255))

  The Notion connector now exposes read actions for users, page metadata and complete property values, individual blocks and their children, and AI meeting notes. The actions map directly to Notion API endpoints, return native responses, and support the relevant filtering, sorting, and pagination options.

- **Use connectors with consistent action behavior** ([#8230](https://github.com/flwrlabs/flower/pull/8230), [#8234](https://github.com/flwrlabs/flower/pull/8234), [#8235](https://github.com/flwrlabs/flower/pull/8235), [#8254](https://github.com/flwrlabs/flower/pull/8254))

  Built-in and OAuth connectors now share the same definition and registry model. Filesystem operations run as connector tasks, record separate usage events, and return structured errors instead of terminating AgentApps, while connector actions explicitly default to non-strict schemas to preserve optional arguments across model APIs.

- **Reply reliably from SuperNode AgentApps** ([#8249](https://github.com/flwrlabs/flower/pull/8249), [#8258](https://github.com/flwrlabs/flower/pull/8258), [#8259](https://github.com/flwrlabs/flower/pull/8259), [#8261](https://github.com/flwrlabs/flower/pull/8261))

  SuperNode AgentApps now use a dedicated reply tool that derives the destination and reply-to identifiers from the received instruction, leaving only the payload for the model to supply. Failed tasks and expired task tokens queue an error reply unless a reply is already pending.

- **Run AgentApps through Flower Chat** ([#8243](https://github.com/flwrlabs/flower/pull/8243), [#8244](https://github.com/flwrlabs/flower/pull/8244), [#8253](https://github.com/flwrlabs/flower/pull/8253))

  Set `FLWR_CHAT_SUPERLINK` to choose the connection used by `flwr chat`, including its TLS, authentication, federation, and AgentApp discovery settings. The AgentApp guides and example now center on Flower Chat and `agent.prompt`, replacing obsolete `flwr run` and run-configuration input instructions.

- **Run sparse federated learning experiments with SSFL** ([#7900](https://github.com/flwrlabs/flower/pull/7900))

  The new SSFL baseline implements static sparse federated learning with the Message API, client-side saliency scoring, global mask aggregation, and sample-weighted sparse FedAvg. It includes ResNet-18 experiments for CIFAR-10 and CIFAR-100, paper-scale configurations, communication accounting, and reproduction guidance.

- **Focus Runtime API access logs on failures** ([#8260](https://github.com/flwrlabs/flower/pull/8260))

  Successful node lookups, log uploads, and task heartbeats are now hidden from Runtime API access logs unless DEBUG logging is enabled, while `4xx` and `5xx` responses remain visible.

- **General improvements** ([#8221](https://github.com/flwrlabs/flower/pull/8221), [#8229](https://github.com/flwrlabs/flower/pull/8229), [#8242](https://github.com/flwrlabs/flower/pull/8242), [#8256](https://github.com/flwrlabs/flower/pull/8256))

  As always, many parts of the Flower framework and quality infrastructure were improved and updated.
