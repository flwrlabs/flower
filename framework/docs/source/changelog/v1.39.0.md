### What's new?

- **Get faster agent responses** ([#8225](https://github.com/flwrlabs/flower/pull/8225), [#8226](https://github.com/flwrlabs/flower/pull/8226), [#8227](https://github.com/flwrlabs/flower/pull/8227), [#8231](https://github.com/flwrlabs/flower/pull/8231), [#8232](https://github.com/flwrlabs/flower/pull/8232), [#8233](https://github.com/flwrlabs/flower/pull/8233), [#8238](https://github.com/flwrlabs/flower/pull/8238))

  AgentApps can respond faster, especially in Kubernetes deployments using warm Pods. Preloaded AgentApp and Connector workers reduce the delay before work begins, and a single task-acquisition request removes a startup round trip for both Kubernetes and subprocess execution.

- **Use connectors in shared federations** ([#8210](https://github.com/flwrlabs/flower/pull/8210), [#8237](https://github.com/flwrlabs/flower/pull/8237), [#8239](https://github.com/flwrlabs/flower/pull/8239), [#8240](https://github.com/flwrlabs/flower/pull/8240), [#8265](https://github.com/flwrlabs/flower/pull/8265))

  Connector storage, OAuth sessions, APIs, and task metadata now carry federation scope, allowing members to connect, list, disconnect, and use connector-backed runs in shared federations. Federations can now keep multiple connections to the same provider, and select one connection of each provider per run.

- **Read Notion users, pages, properties, blocks, meeting notes, and databases** ([#8245](https://github.com/flwrlabs/flower/pull/8245), [#8252](https://github.com/flwrlabs/flower/pull/8252), [#8255](https://github.com/flwrlabs/flower/pull/8255), [#8266](https://github.com/flwrlabs/flower/pull/8266))

  The Notion connector now exposes read actions for users, page metadata and complete property values, individual blocks and their children, AI meeting notes, and database metadata with associated data source references. The actions map directly to Notion API endpoints, return native responses, and support the relevant filtering, sorting, and pagination options.

- **Run AgentApps through `flwr chat`** ([#8243](https://github.com/flwrlabs/flower/pull/8243), [#8244](https://github.com/flwrlabs/flower/pull/8244), [#8253](https://github.com/flwrlabs/flower/pull/8253))

  Set `FLWR_CHAT_SUPERLINK` to choose the connection used by `flwr chat`. The AgentApp guides and example now center on `flwr chat` and `agent.prompt`, replacing obsolete `flwr run` and run-configuration input instructions.

- **Run sparse federated learning experiments with SSFL** ([#7900](https://github.com/flwrlabs/flower/pull/7900))

  The new SSFL baseline implements static sparse federated learning with the Message API, client-side saliency scoring, global mask aggregation, and sample-weighted sparse FedAvg. It includes ResNet-18 experiments for CIFAR-10 and CIFAR-100, paper-scale configurations, communication accounting, and reproduction guidance.

- **General improvements** ([#8221](https://github.com/flwrlabs/flower/pull/8221), [#8229](https://github.com/flwrlabs/flower/pull/8229), [#8230](https://github.com/flwrlabs/flower/pull/8230), [#8234](https://github.com/flwrlabs/flower/pull/8234), [#8235](https://github.com/flwrlabs/flower/pull/8235), [#8242](https://github.com/flwrlabs/flower/pull/8242), [#8249](https://github.com/flwrlabs/flower/pull/8249), [#8254](https://github.com/flwrlabs/flower/pull/8254), [#8256](https://github.com/flwrlabs/flower/pull/8256), [#8258](https://github.com/flwrlabs/flower/pull/8258), [#8259](https://github.com/flwrlabs/flower/pull/8259), [#8260](https://github.com/flwrlabs/flower/pull/8260), [#8261](https://github.com/flwrlabs/flower/pull/8261), [#8268](https://github.com/flwrlabs/flower/pull/8268), [#8270](https://github.com/flwrlabs/flower/pull/8270))

  As always, many parts of the Flower framework and quality infrastructure were improved and updated.
