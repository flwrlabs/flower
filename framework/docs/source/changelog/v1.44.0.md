### What's new?

- **Run AgentApps in shared Spaces** ([#8444](https://github.com/flwrlabs/flower/pull/8444), [#8477](https://github.com/flwrlabs/flower/pull/8477), [#8481](https://github.com/flwrlabs/flower/pull/8481), [#8484](https://github.com/flwrlabs/flower/pull/8484), [#8485](https://github.com/flwrlabs/flower/pull/8485), [#8494](https://github.com/flwrlabs/flower/pull/8494), [#8498](https://github.com/flwrlabs/flower/pull/8498), [#8500](https://github.com/flwrlabs/flower/pull/8500), [#8507](https://github.com/flwrlabs/flower/pull/8507), [#8511](https://github.com/flwrlabs/flower/pull/8511), [#8512](https://github.com/flwrlabs/flower/pull/8512), [#8517](https://github.com/flwrlabs/flower/pull/8517), [#8521](https://github.com/flwrlabs/flower/pull/8521), [#8523](https://github.com/flwrlabs/flower/pull/8523), [#8525](https://github.com/flwrlabs/flower/pull/8525), [#8527](https://github.com/flwrlabs/flower/pull/8527), [#8528](https://github.com/flwrlabs/flower/pull/8528), [#8532](https://github.com/flwrlabs/flower/pull/8532), [#8533](https://github.com/flwrlabs/flower/pull/8533), [#8534](https://github.com/flwrlabs/flower/pull/8534), [#8536](https://github.com/flwrlabs/flower/pull/8536), [#8548](https://github.com/flwrlabs/flower/pull/8548))

  Agents now receive a Space automatically and can run their AgentApp when unread messages arrive. Space AgentApps can read and send messages, inspect their identity and traces, and reuse Agent-scoped compacted contexts through authenticated Runtime APIs; the Hub AgentApp also includes the configured Agent description in model instructions.

- **Bootstrap and stream Agent and Space updates** ([#8504](https://github.com/flwrlabs/flower/pull/8504), [#8505](https://github.com/flwrlabs/flower/pull/8505), [#8506](https://github.com/flwrlabs/flower/pull/8506), [#8513](https://github.com/flwrlabs/flower/pull/8513), [#8522](https://github.com/flwrlabs/flower/pull/8522))

  Control clients can fetch the caller's visible Agents and Spaces with a user-feed cursor, then replay journaled updates without missing concurrent changes. Operators can tune stream polling with `FLWR_USER_EVENTS_STREAM_INTERVAL`.

- **Use Agent-owned connectors in Space sessions** ([#8545](https://github.com/flwrlabs/flower/pull/8545), [#8546](https://github.com/flwrlabs/flower/pull/8546), [#8547](https://github.com/flwrlabs/flower/pull/8547), [#8550](https://github.com/flwrlabs/flower/pull/8550), [#8551](https://github.com/flwrlabs/flower/pull/8551), [#8552](https://github.com/flwrlabs/flower/pull/8552))

  Agents can own connectors independently of federations. The Control API supports connecting and disconnecting Agent connectors, while Space sessions can discover and use multiple connected accounts through distinct tools without exposing credentials.

- **Store AgentApp files through Runtime** ([#8453](https://github.com/flwrlabs/flower/pull/8453))

  AgentApps can now put, get, list, and delete files through authenticated Runtime APIs. Files are scoped to the executing Agent, with revision preconditions, prefix and cursor filtering, and paginated listing.

- **Prepare Space-based Agent automations** ([#8554](https://github.com/flwrlabs/flower/pull/8554), [#8555](https://github.com/flwrlabs/flower/pull/8555), [#8556](https://github.com/flwrlabs/flower/pull/8556), [#8558](https://github.com/flwrlabs/flower/pull/8558))

  Automation state can now record Agent ownership, and Agents and Space messages carry the default Space and visibility metadata needed for a future Space automation path. Existing automations and messages remain compatible; this release does not change automation creation or dispatch.

- **Reduce warm worker dispatch latency** ([#8482](https://github.com/flwrlabs/flower/pull/8482), [#8487](https://github.com/flwrlabs/flower/pull/8487), [#8490](https://github.com/flwrlabs/flower/pull/8490))

  Prestarted AgentApp and connector workers now use a lightweight `python -m` relay with lazy package exports, reducing median handoff time from 480 ms to 101 ms in local Kubernetes benchmarks.

- **Configure run-event polling** ([#8489](https://github.com/flwrlabs/flower/pull/8489))

  Operators can set `FLWR_RUN_EVENTS_STREAM_INTERVAL` to tune Control API run-event polling between 0.01 and 60 seconds. Each stream uses the value resolved when it starts and defaults to 0.5 seconds.

- **Create federations in authorized namespaces** ([#8503](https://github.com/flwrlabs/flower/pull/8503))

  `CreateFederationRequest.handle` can select a namespace other than the authenticated caller's handle. Federation managers must authorize the selected namespace for the authenticated actor; omitting the field preserves the existing behavior.

- **Enforce federation membership for run reads** ([#8520](https://github.com/flwrlabs/flower/pull/8520))

  Run listings and artifact download URLs now require current federation membership in addition to submission ownership, so former members can no longer read federation runs through those paths.

- **Observe model request preparation time** ([#8508](https://github.com/flwrlabs/flower/pull/8508))

  Runtime Responses now publish authentication and request-decoding timings before the model round trip, without recording credentials or request bodies.

- **General improvements** ([#8469](https://github.com/flwrlabs/flower/pull/8469), [#8480](https://github.com/flwrlabs/flower/pull/8480), [#8483](https://github.com/flwrlabs/flower/pull/8483), [#8497](https://github.com/flwrlabs/flower/pull/8497), [#8509](https://github.com/flwrlabs/flower/pull/8509), [#8514](https://github.com/flwrlabs/flower/pull/8514), [#8516](https://github.com/flwrlabs/flower/pull/8516), [#8530](https://github.com/flwrlabs/flower/pull/8530), [#8539](https://github.com/flwrlabs/flower/pull/8539))

  As always, many parts of the Flower framework and quality infrastructure were improved and updated.
