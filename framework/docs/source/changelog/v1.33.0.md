### What's new?

- **Chat with Flower Agent from your terminal (experimental)** ([#7691](https://github.com/flwrlabs/flower/pull/7691), [#7695](https://github.com/flwrlabs/flower/pull/7695), [#7721](https://github.com/flwrlabs/flower/pull/7721), [#7723](https://github.com/flwrlabs/flower/pull/7723), [#7729](https://github.com/flwrlabs/flower/pull/7729), [#7730](https://github.com/flwrlabs/flower/pull/7730), [#7731](https://github.com/flwrlabs/flower/pull/7731), [#7733](https://github.com/flwrlabs/flower/pull/7733), [#7739](https://github.com/flwrlabs/flower/pull/7739))

  Run `flwr chat` to start an interactive Flower Agent session on SuperGrid. Responses stream into the terminal, `Ctrl+C` stops the current response, slash commands are autocompleted, and reasoning and web-search activity can be expanded when needed. `/new` starts a new run series. Run series group related runs for tracking; they do not automatically provide conversation history to the model. Flower Agent is experimental and requires a SuperGrid account with access to Flower Agent.

- **Build AgentApps with automations and connectors (experimental)** ([#7540](https://github.com/flwrlabs/flower/pull/7540), [#7552](https://github.com/flwrlabs/flower/pull/7552), [#7555](https://github.com/flwrlabs/flower/pull/7555), [#7558](https://github.com/flwrlabs/flower/pull/7558), [#7565](https://github.com/flwrlabs/flower/pull/7565), [#7567](https://github.com/flwrlabs/flower/pull/7567), [#7571](https://github.com/flwrlabs/flower/pull/7571), [#7573](https://github.com/flwrlabs/flower/pull/7573), [#7587](https://github.com/flwrlabs/flower/pull/7587), [#7591](https://github.com/flwrlabs/flower/pull/7591), [#7597](https://github.com/flwrlabs/flower/pull/7597), [#7598](https://github.com/flwrlabs/flower/pull/7598), [#7608](https://github.com/flwrlabs/flower/pull/7608), [#7610](https://github.com/flwrlabs/flower/pull/7610), [#7614](https://github.com/flwrlabs/flower/pull/7614), [#7621](https://github.com/flwrlabs/flower/pull/7621), [#7623](https://github.com/flwrlabs/flower/pull/7623), [#7664](https://github.com/flwrlabs/flower/pull/7664), [#7702](https://github.com/flwrlabs/flower/pull/7702), [#7704](https://github.com/flwrlabs/flower/pull/7704))

  AgentApp developers can give models runtime-provided connector tools without embedding connector implementations or provider credentials in their apps. OAuth connections and credentials are scoped to each run. Persisted automations can schedule one-time or recurring AgentApp runs and can be started, listed, and stopped through the Control API.

- **Track task usage of `AgentApp`** ([#7517](https://github.com/flwrlabs/flower/pull/7517), [#7521](https://github.com/flwrlabs/flower/pull/7521), [#7523](https://github.com/flwrlabs/flower/pull/7523), [#7537](https://github.com/flwrlabs/flower/pull/7537), [#7640](https://github.com/flwrlabs/flower/pull/7640))

  Agent runs now record fine-grained usage per task, improving the accuracy of usage reporting for individual runs.

- **Learn how to build and run Flower Agent (experimental)** ([#7699](https://github.com/flwrlabs/flower/pull/7699), [#7705](https://github.com/flwrlabs/flower/pull/7705), [#7707](https://github.com/flwrlabs/flower/pull/7707), [#7711](https://github.com/flwrlabs/flower/pull/7711), [#7724](https://github.com/flwrlabs/flower/pull/7724), [#7727](https://github.com/flwrlabs/flower/pull/7727))

  New [Flower Agent documentation](https://flower.ai/docs/agent/) guides you through chatting with the built-in AgentApp, building your own AgentApp, running it locally or on SuperGrid, and adding connector tool calls. Flower Agent APIs are experimental and likely to change in incompatible ways in future releases.

  KubernetesExecutor deployments can now attach custom volumes and volume mounts to TaskExecutor pods, making it easier to provide datasets, caches, or other runtime files while protecting Flower's reserved credential mounts.

### Incompatible changes

- **Standardize federation IDs in JSON output and database schema** ([#7519](https://github.com/flwrlabs/flower/pull/7519), [#7529](https://github.com/flwrlabs/flower/pull/7529))

  Federation IDs are now consistently represented as `@<account-name>/<federation-name>`. Update integrations using `flwr ls --json` to read `federation-id` instead of `federation`, and integrations using `flwr federation ls --json` to read `id` instead of `name`. The corresponding database columns are migrated from `federation` to `federation_id`.

- **Remove the legacy TensorBoard helper** ([#7554](https://github.com/flwrlabs/flower/pull/7554))

  `flwr.server.utils.tensorboard` has been removed. Applications importing this deprecated utility must replace it with their own strategy metrics or TensorBoard integration before upgrading.

- **Remove the experimental REST Fleet transport** ([#7520](https://github.com/flwrlabs/flower/pull/7520), [#7560](https://github.com/flwrlabs/flower/pull/7560), [#7580](https://github.com/flwrlabs/flower/pull/7580))

  The experimental REST Fleet API, client transport, and `rest` installation extra have been removed. Replace REST transport configuration with the default `grpc-rere` transport or `grpc-adapter`, and install `flwr` without the `rest` extra.
