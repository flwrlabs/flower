### What's new?

- **Prepare the Flower CLI for the HTTP Control API** ([#8005](https://github.com/flwrlabs/flower/pull/8005), [#8008](https://github.com/flwrlabs/flower/pull/8008), [#8009](https://github.com/flwrlabs/flower/pull/8009), [#8018](https://github.com/flwrlabs/flower/pull/8018), [#8019](https://github.com/flwrlabs/flower/pull/8019), [#8020](https://github.com/flwrlabs/flower/pull/8020), [#8021](https://github.com/flwrlabs/flower/pull/8021), [#8023](https://github.com/flwrlabs/flower/pull/8023), [#8025](https://github.com/flwrlabs/flower/pull/8025), [#8026](https://github.com/flwrlabs/flower/pull/8026), [#8027](https://github.com/flwrlabs/flower/pull/8027), [#8032](https://github.com/flwrlabs/flower/pull/8032))

  The HTTP Control API now covers streaming logs and run events, artifact retrieval, connectors, authentication refresh, and transport-aware app validation. A new `ControlHttpClient` supports the existing endpoints, authentication, and bounded streaming error responses, while CLI error and log paths are prepared for a future HTTP transport switch; the CLI continues to use gRPC in this release.

- **Learn how to find, run, and publish AgentApps** ([#7928](https://github.com/flwrlabs/flower/pull/7928), [#7929](https://github.com/flwrlabs/flower/pull/7929), [#7930](https://github.com/flwrlabs/flower/pull/7930), [#7988](https://github.com/flwrlabs/flower/pull/7988), [#8000](https://github.com/flwrlabs/flower/pull/8000), [#8002](https://github.com/flwrlabs/flower/pull/8002), [#8031](https://github.com/flwrlabs/flower/pull/8031))

  Updated Flower Agent guidance explains how to discover apps in Flower Hub, run them locally or on SuperGrid, use Ollama or the OpenAI SDK, and publish frontend-visible output with `agent.events.emit(...)`. The agent template demonstrates streaming through `/v1/runtime/responses`, and queued events are drained before the publisher shuts down.

- **Use consistent Runtime API address options** ([#8010](https://github.com/flwrlabs/flower/pull/8010), [#8011](https://github.com/flwrlabs/flower/pull/8011), [#8012](https://github.com/flwrlabs/flower/pull/8012), [#8014](https://github.com/flwrlabs/flower/pull/8014), [#8029](https://github.com/flwrlabs/flower/pull/8029))

  SuperExec and task-process commands now use `--runtime-api-address` instead of the remaining AppIO-specific option names. Examples use the SuperNode `--host` and `--port` options introduced in v1.35.0.

- **Make run and result delivery visible to extensions** ([#7998](https://github.com/flwrlabs/flower/pull/7998), [#8038](https://github.com/flwrlabs/flower/pull/8038), [#8039](https://github.com/flwrlabs/flower/pull/8039))

  Run-start hooks now receive best-effort source attribution for HTTP, gRPC, and automation starts. Extensions are also notified when results are delivered for every primary task type, using consistent channel identifiers for logs and chat/task events.

- **Send shared reply objects reliably from SuperNodes** ([#8033](https://github.com/flwrlabs/flower/pull/8033))

  SuperNodes now deduplicate content-addressed objects before uploading a reply, preventing shared descendants in an `ObjectTree` from triggering duplicate push requests and leaving reply objects unavailable to the ServerApp.

- **Configure how often SuperExec polls for tasks** ([#8041](https://github.com/flwrlabs/flower/pull/8041))

  Set `FLWR_SUPEREXEC_TASK_POLL_INTERVAL` to choose a polling interval from 0.01 to 60 seconds. The default is now one second, and Helm environment configuration is documented.

- **Get quieter SuperNode logs by default** ([#8043](https://github.com/flwrlabs/flower/pull/8043))

  `flower-supernode` now hides Uvicorn access logs unless debug logging is enabled. Set `FLWR_LOG_LEVEL=DEBUG` to show them.

- **Explore Endeavor 1.0** ([#8042](https://github.com/flwrlabs/flower/pull/8042))

  New Flower Model documentation describes Endeavor 1.0 preview access, managed and private deployment paths, benchmark results, and safety limitations.

- **General improvements** ([#7996](https://github.com/flwrlabs/flower/pull/7996), [#8004](https://github.com/flwrlabs/flower/pull/8004), [#8013](https://github.com/flwrlabs/flower/pull/8013), [#8016](https://github.com/flwrlabs/flower/pull/8016), [#8034](https://github.com/flwrlabs/flower/pull/8034))

  As always, many parts of the Flower framework and quality infrastructure were improved and updated.
