### What's new?

- **Use the Flower CLI over HTTP Control API** ([#8028](https://github.com/flwrlabs/flower/pull/8028), [#8045](https://github.com/flwrlabs/flower/pull/8045), [#8046](https://github.com/flwrlabs/flower/pull/8046), [#8047](https://github.com/flwrlabs/flower/pull/8047), [#8055](https://github.com/flwrlabs/flower/pull/8055), [#8057](https://github.com/flwrlabs/flower/pull/8057), [#8070](https://github.com/flwrlabs/flower/pull/8070), [#8072](https://github.com/flwrlabs/flower/pull/8072), [#8073](https://github.com/flwrlabs/flower/pull/8073), [#8076](https://github.com/flwrlabs/flower/pull/8076), [#8077](https://github.com/flwrlabs/flower/pull/8077), [#8084](https://github.com/flwrlabs/flower/pull/8084), [#8085](https://github.com/flwrlabs/flower/pull/8085), [#8087](https://github.com/flwrlabs/flower/pull/8087), [#8089](https://github.com/flwrlabs/flower/pull/8089), [#8093](https://github.com/flwrlabs/flower/pull/8093), [#8099](https://github.com/flwrlabs/flower/pull/8099))

  The Flower CLI now sends Control API requests over HTTP, including Bearer-token authentication and refresh, TLS-aware initialization, local SuperLink readiness checks, and CLI request identification. The gRPC Control API is disabled by default, `--control-api-address` is deprecated in favor of `--host` and `--port`, and SuperGrid configuration and deployment guides now use `api.flower.ai` and HTTP port 8000.

- **Run tasks in warm Kubernetes executor pools** ([#8088](https://github.com/flwrlabs/flower/pull/8088), [#8096](https://github.com/flwrlabs/flower/pull/8096), [#8098](https://github.com/flwrlabs/flower/pull/8098), [#8103](https://github.com/flwrlabs/flower/pull/8103), [#8108](https://github.com/flwrlabs/flower/pull/8108), [#8125](https://github.com/flwrlabs/flower/pull/8125), [#8134](https://github.com/flwrlabs/flower/pull/8134), [#8135](https://github.com/flwrlabs/flower/pull/8135), [#8140](https://github.com/flwrlabs/flower/pull/8140))

  Configured Kubernetes warm pools can dispatch AgentApp tasks through pre-started `TaskExecutor` Pods, with bounded stdin token handoff, TLS support, compatibility checks, replenishment, and safe cold-start fallback. Trusted Model and Connector pool entries are also supported, while dependency-installation timing and dispatch logs make pool behavior observable.

- **Manage AgentApp context and inspect event history** ([#8048](https://github.com/flwrlabs/flower/pull/8048), [#8058](https://github.com/flwrlabs/flower/pull/8058), [#8060](https://github.com/flwrlabs/flower/pull/8060), [#8101](https://github.com/flwrlabs/flower/pull/8101), [#8102](https://github.com/flwrlabs/flower/pull/8102), [#8104](https://github.com/flwrlabs/flower/pull/8104), [#8110](https://github.com/flwrlabs/flower/pull/8110), [#8127](https://github.com/flwrlabs/flower/pull/8127))

  AgentApps can retrieve persisted primary-task events across a run series with `agent.events.get_trace()`, while Control API clients can list series events and inspect each run's lifecycle. Inputs and tool calls are recorded as standard events, the first text delta is delivered eagerly, context is no longer mutated automatically, and the unused `responses.create()` AgentApp API has been removed.

- **Name and rename AgentApp conversations** ([#8123](https://github.com/flwrlabs/flower/pull/8123), [#8128](https://github.com/flwrlabs/flower/pull/8128), [#8131](https://github.com/flwrlabs/flower/pull/8131))

  New AgentApp conversations receive a concise generated title during their first run, with a prompt-based fallback if model generation fails. Authenticated Control API clients can rename a conversation by updating its run series description.

- **Load local AgentApps in `flwr chat`** ([#8105](https://github.com/flwrlabs/flower/pull/8105))

  Use `/load <path>` to select and test a local AgentApp interactively. `flwr chat` rebuilds the app before every message and starts a new run series when its specification or FAB content changes.

- **Get current Hub apps and richer federation membership data** ([#8068](https://github.com/flwrlabs/flower/pull/8068), [#8078](https://github.com/flwrlabs/flower/pull/8078))

  Hub apps now resolve their latest FAB for every run while custom apps remain pinned to their stored FAB hash. Federation responses include a bounded member preview and the total active-member count.

- **Use Open Connector-compatible schemas** ([#8075](https://github.com/flwrlabs/flower/pull/8075))

  Connector actions and arguments now follow Open Connector conventions, including pagination, filtering, and sorting parameters. Attio requests are translated to its provider API, and Slack, GitHub, and Notion responses use normalized output schemas.

- **Consolidate the HTTP Runtime API** ([#8115](https://github.com/flwrlabs/flower/pull/8115), [#8116](https://github.com/flwrlabs/flower/pull/8116), [#8120](https://github.com/flwrlabs/flower/pull/8120), [#8129](https://github.com/flwrlabs/flower/pull/8129), [#8137](https://github.com/flwrlabs/flower/pull/8137), [#8139](https://github.com/flwrlabs/flower/pull/8139))

  SuperLink and SuperNode now share one HTTP Runtime API router with common state and authentication dependencies and typed component handlers. The obsolete Runtime gRPC service definition, authentication interceptors, and interceptor factories have been removed.

- **Configure Runtime API TLS with consistent options** ([#8109](https://github.com/flwrlabs/flower/pull/8109), [#8113](https://github.com/flwrlabs/flower/pull/8113))

  SuperNode now uses `--ssl-certfile`, `--ssl-keyfile`, and `--ssl-ca-certfile` for Runtime API TLS while retaining the former `--appio-ssl-*` options as deprecated aliases. SuperLink help now clarifies that the same `--ssl-*` options secure its Fleet, Control, and Runtime APIs.

- **Deploy SuperNodes using Slurm** ([#8074](https://github.com/flwrlabs/flower/pull/8074))

  A new guide covers running SuperNodes as Slurm jobs with subprocess or process isolation, including separate SuperExec jobs, GPU allocation, and scheduler-selected nodes.

- **Reject invalid `FedTrimmedAvg` trimming fractions** ([#7946](https://github.com/flwrlabs/flower/pull/7946))

  ServerApp and legacy `FedTrimmedAvg` strategies now require `beta` to be in `[0, 0.5)`, preventing invalid trimming from producing `NaN` model parameters.

- **Preserve nested configuration keys** ([#8071](https://github.com/flwrlabs/flower/pull/8071))

  Partial nested configuration overrides now retain sibling keys from the base configuration instead of replacing the entire nested dictionary.

- **Support task messages on SuperNodes** ([#8142](https://github.com/flwrlabs/flower/pull/8142))

  Task-message validation and construction now use the owning `CoreState` node identity, allowing messages created for tasks running on a SuperNode to be accepted correctly.

- **General improvements** ([#8049](https://github.com/flwrlabs/flower/pull/8049), [#8056](https://github.com/flwrlabs/flower/pull/8056), [#8064](https://github.com/flwrlabs/flower/pull/8064), [#8066](https://github.com/flwrlabs/flower/pull/8066), [#8067](https://github.com/flwrlabs/flower/pull/8067), [#8080](https://github.com/flwrlabs/flower/pull/8080), [#8095](https://github.com/flwrlabs/flower/pull/8095), [#8112](https://github.com/flwrlabs/flower/pull/8112), [#8114](https://github.com/flwrlabs/flower/pull/8114), [#8118](https://github.com/flwrlabs/flower/pull/8118), [#8119](https://github.com/flwrlabs/flower/pull/8119), [#8124](https://github.com/flwrlabs/flower/pull/8124), [#8126](https://github.com/flwrlabs/flower/pull/8126), [#8136](https://github.com/flwrlabs/flower/pull/8136))

  As always, many parts of the Flower framework and quality infrastructure were improved and updated.

### Incompatible changes

- **Remove deprecated SuperLink Exec API options** ([#8100](https://github.com/flwrlabs/flower/pull/8100))

  SuperLink no longer accepts `--exec-api-address`, `--executor`, `--executor-dir`, or `--executor-config`. Remove these long-deprecated options from SuperLink launch configurations.

- **Update SuperLink TLS configuration** ([#8106](https://github.com/flwrlabs/flower/pull/8106))

  SuperLink now uses `--ssl-certfile`, `--ssl-keyfile`, and `--ssl-ca-certfile` to secure its Fleet, Control, and Runtime APIs with one certificate set. Replace any `--appio-ssl-*` options with these shared options; the removed flags now terminate startup.
