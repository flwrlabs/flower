### What's new?

With this release, both RuntimeAPI and ControlAPI now use HTTP, making traffic easier to inspect, debug, and integrate with standard HTTP tooling. Logging is also richer, and the default log output has changed slightly to improve readability. To see all logs, enable [verbose logging](https://flower.ai/docs/framework/1.36/en/how-to-configure-logging.html) for SuperLink, SuperNode, or SuperExec. SuperLink no longer periodically logs which SuperNodes are connected; you can query this information at any time by running `flwr supernode ls`.

- **Flower CLI switches to HTTP** ([#8028](https://github.com/flwrlabs/flower/pull/8028), [#8045](https://github.com/flwrlabs/flower/pull/8045), [#8046](https://github.com/flwrlabs/flower/pull/8046), [#8047](https://github.com/flwrlabs/flower/pull/8047), [#8055](https://github.com/flwrlabs/flower/pull/8055), [#8057](https://github.com/flwrlabs/flower/pull/8057), [#8070](https://github.com/flwrlabs/flower/pull/8070), [#8072](https://github.com/flwrlabs/flower/pull/8072), [#8073](https://github.com/flwrlabs/flower/pull/8073), [#8076](https://github.com/flwrlabs/flower/pull/8076), [#8077](https://github.com/flwrlabs/flower/pull/8077), [#8084](https://github.com/flwrlabs/flower/pull/8084), [#8085](https://github.com/flwrlabs/flower/pull/8085), [#8087](https://github.com/flwrlabs/flower/pull/8087), [#8089](https://github.com/flwrlabs/flower/pull/8089), [#8093](https://github.com/flwrlabs/flower/pull/8093), [#8099](https://github.com/flwrlabs/flower/pull/8099))

  The Flower CLI now sends Control API requests over HTTP. The gRPC Control API is disabled by default, and `--control-api-address` is deprecated in favor of `--host` and `--port`. SuperGrid configuration and deployment guides now use api.flower.ai. If your [Flower Configuration](https://flower.ai/docs/framework/1.37/en/ref-flower-configuration.html) file defines a custom `SuperLink` connection, you must update it for the switch from gRPC to HTTP; in most cases, only the port needs to change.

- **Manage AgentApp context and inspect event history** ([#8048](https://github.com/flwrlabs/flower/pull/8048), [#8058](https://github.com/flwrlabs/flower/pull/8058), [#8060](https://github.com/flwrlabs/flower/pull/8060), [#8101](https://github.com/flwrlabs/flower/pull/8101), [#8102](https://github.com/flwrlabs/flower/pull/8102), [#8104](https://github.com/flwrlabs/flower/pull/8104), [#8110](https://github.com/flwrlabs/flower/pull/8110), [#8127](https://github.com/flwrlabs/flower/pull/8127))

  AgentApps can retrieve persisted primary-task events across a run series with `agent.events.get_trace()`, while Control API clients can list series events and inspect each run's lifecycle. Inputs and tool calls are recorded as standard events, the first text delta is delivered eagerly, context is no longer mutated automatically, and the unused `responses.create()` AgentApp API has been removed.

- **Name and rename AgentApp conversations** ([#8123](https://github.com/flwrlabs/flower/pull/8123), [#8128](https://github.com/flwrlabs/flower/pull/8128), [#8131](https://github.com/flwrlabs/flower/pull/8131))

  New AgentApp conversations receive a concise generated title during their first run, with a prompt-based fallback if model generation fails. Authenticated Control API clients can rename a conversation by updating its run series description.

- **Load local AgentApps in `flwr chat`** ([#8105](https://github.com/flwrlabs/flower/pull/8105))

  Use `/load <path>` to select and test a local AgentApp interactively. `flwr chat` rebuilds the app before every message and starts a new run series when its specification or FAB content changes.

- **Configure Runtime API TLS with consistent options** ([#8109](https://github.com/flwrlabs/flower/pull/8109), [#8113](https://github.com/flwrlabs/flower/pull/8113))

  SuperNode now uses `--ssl-certfile`, `--ssl-keyfile`, and `--ssl-ca-certfile` for Runtime API TLS while retaining the former `--appio-ssl-*` options as deprecated aliases. SuperLink help now clarifies that the same `--ssl-*` options secure its Fleet, Control, and Runtime APIs.

- **Deploy SuperNodes using Slurm** ([#8074](https://github.com/flwrlabs/flower/pull/8074))

  A new guide covers running SuperNodes as Slurm jobs with subprocess or process isolation, including separate SuperExec jobs, GPU allocation, and scheduler-selected nodes.

- **Reject invalid `FedTrimmedAvg` trimming fractions** ([#7946](https://github.com/flwrlabs/flower/pull/7946))

  ServerApp and legacy `FedTrimmedAvg` strategies now require `beta` to be in `[0, 0.5)`, preventing invalid trimming from producing `NaN` model parameters.

- **Faster AgentApp runs on SuperGrid with warm Kubernetes Pods** ([#8088](https://github.com/flwrlabs/flower/pull/8088), [#8096](https://github.com/flwrlabs/flower/pull/8096), [#8098](https://github.com/flwrlabs/flower/pull/8098), [#8103](https://github.com/flwrlabs/flower/pull/8103), [#8108](https://github.com/flwrlabs/flower/pull/8108), [#8125](https://github.com/flwrlabs/flower/pull/8125), [#8134](https://github.com/flwrlabs/flower/pull/8134), [#8135](https://github.com/flwrlabs/flower/pull/8135), [#8140](https://github.com/flwrlabs/flower/pull/8140))

  Configured Kubernetes warm pools can dispatch AgentApp tasks through pre-started `TaskExecutor` Pods, with bounded stdin token handoff, TLS support, compatibility checks, replenishment, and safe cold-start fallback. Trusted Model and Connector pool entries are also supported, while dependency-installation timing and dispatch logs make pool behavior observable.

- **Faster Flower Hub app runs with local caching** ([#8082](https://github.com/flwrlabs/flower/pull/8082))

  SuperLink can now reuse cached FABs for unversioned Flower Hub apps instead of downloading them for every run, reducing startup latency. Cache entries older than five minutes can still be used immediately while SuperLink refreshes and validates the latest version in the background.

- **General improvements** ([#8049](https://github.com/flwrlabs/flower/pull/8049), [#8056](https://github.com/flwrlabs/flower/pull/8056), [#8064](https://github.com/flwrlabs/flower/pull/8064), [#8066](https://github.com/flwrlabs/flower/pull/8066), [#8067](https://github.com/flwrlabs/flower/pull/8067), [#8068](https://github.com/flwrlabs/flower/pull/8068), [#8071](https://github.com/flwrlabs/flower/pull/8071), [#8075](https://github.com/flwrlabs/flower/pull/8075), [#8078](https://github.com/flwrlabs/flower/pull/8078), [#8080](https://github.com/flwrlabs/flower/pull/8080), [#8095](https://github.com/flwrlabs/flower/pull/8095), [#8112](https://github.com/flwrlabs/flower/pull/8112), [#8114](https://github.com/flwrlabs/flower/pull/8114), [#8115](https://github.com/flwrlabs/flower/pull/8115), [#8116](https://github.com/flwrlabs/flower/pull/8116), [#8118](https://github.com/flwrlabs/flower/pull/8118), [#8119](https://github.com/flwrlabs/flower/pull/8119), [#8120](https://github.com/flwrlabs/flower/pull/8120), [#8124](https://github.com/flwrlabs/flower/pull/8124), [#8126](https://github.com/flwrlabs/flower/pull/8126), [#8129](https://github.com/flwrlabs/flower/pull/8129), [#8136](https://github.com/flwrlabs/flower/pull/8136), [#8137](https://github.com/flwrlabs/flower/pull/8137), [#8139](https://github.com/flwrlabs/flower/pull/8139), [#8142](https://github.com/flwrlabs/flower/pull/8142), [#8144](https://github.com/flwrlabs/flower/pull/8144), [#8149](https://github.com/flwrlabs/flower/pull/8149))

### Incompatible changes

- **Remove deprecated SuperLink Exec API options** ([#8100](https://github.com/flwrlabs/flower/pull/8100))

  SuperLink no longer accepts `--exec-api-address`, `--executor`, `--executor-dir`, or `--executor-config`. Remove these long-deprecated options from SuperLink launch configurations.

- **Update SuperLink TLS configuration** ([#8106](https://github.com/flwrlabs/flower/pull/8106))

  SuperLink now uses `--ssl-certfile`, `--ssl-keyfile`, and `--ssl-ca-certfile` to secure its Fleet, Control, and Runtime APIs with one certificate set. Replace any `--appio-ssl-*` options with these shared options; the removed flags now terminate startup.
