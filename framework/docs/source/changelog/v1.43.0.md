### What's new?

- **Deliver messages by destination** ([#8385](https://github.com/flwrlabs/flower/pull/8385), [#8409](https://github.com/flwrlabs/flower/pull/8409), [#8415](https://github.com/flwrlabs/flower/pull/8415), [#8429](https://github.com/flwrlabs/flower/pull/8429))

  Production and simulation now use a shared destination-based inbox for message delivery. Optional correlation filters support unfiltered pulls, multiple replies, and unsolicited messages, while the legacy instruction/reply storage has been removed.

- **Stop strategies before all rounds complete** ([#8401](https://github.com/flwrlabs/flower/pull/8401))

  Pass a `should_stop(server_round, result)` callback to `Strategy.start()` to stop an FL run after any completed round and return the current model and collected metrics through the normal exit path.

- **Trace Agent latency across execution phases** ([#8411](https://github.com/flwrlabs/flower/pull/8411), [#8414](https://github.com/flwrlabs/flower/pull/8414))

  Agent tracing now records successful task acquisition, worker startup, model requests, first-output delivery, and connector execution. Tracing initializes before prestarted workers report readiness and remains best-effort without logging payloads.

- **Call model providers directly from Runtime** ([#8425](https://github.com/flwrlabs/flower/pull/8425), [#8431](https://github.com/flwrlabs/flower/pull/8431), [#8432](https://github.com/flwrlabs/flower/pull/8432), [#8449](https://github.com/flwrlabs/flower/pull/8449))

  Runtime Responses now call the configured inference endpoint directly for every model while preserving the AgentApp API, streaming, cancellation, deadlines, and usage accounting. The obsolete Model worker, `flwr-model` CLI, message transport, and `TaskType.MODEL` have been removed.

- **Store versioned files in CoreState** ([#8428](https://github.com/flwrlabs/flower/pull/8428), [#8438](https://github.com/flwrlabs/flower/pull/8438), [#8448](https://github.com/flwrlabs/flower/pull/8448))

  CoreState now stores files and immutable revision history in memory or SQL, with revision preconditions, prefix-filtered listing, and soft deletion. Runtime protobuf messages and HTTP client methods are available, while the server-side Runtime handlers remain unimplemented in this release.

- **Create and list persistent Agents** ([#8430](https://github.com/flwrlabs/flower/pull/8430), [#8435](https://github.com/flwrlabs/flower/pull/8435), [#8439](https://github.com/flwrlabs/flower/pull/8439), [#8440](https://github.com/flwrlabs/flower/pull/8440), [#8441](https://github.com/flwrlabs/flower/pull/8441), [#8445](https://github.com/flwrlabs/flower/pull/8445))

  Authenticated Control API callers can now create Agents and list the Agents owned by their account, backed by CoreState persistence. A new conversation schema stores Agent and user participants and their ordered text messages, while an initial Control API contract defines conversation creation and listing ahead of server integration.

- **Handle structured errors from protobuf HTTP APIs** ([#8460](https://github.com/flwrlabs/flower/pull/8460))

  Protobuf HTTP clients can opt into `FlowerErrorHttpInterceptor` to receive recognized error responses as `FlowerError` instances. Unrecognized HTTP failures retain their existing exception and retry behavior.

- **Authenticate SuperExec requests in standalone Uvicorn deployments** ([#8461](https://github.com/flwrlabs/flower/pull/8461))

  Starting SuperLink with Uvicorn now loads the SuperExec authentication secret from `FLWR_SUPEREXEC_AUTH_SECRET_FILE`. Configured secret files that are missing, unreadable, or empty cause startup to fail instead of leaving requests unsigned.

- **Use HTTP for Fleet and Control APIs** ([#8458](https://github.com/flwrlabs/flower/pull/8458), [#8462](https://github.com/flwrlabs/flower/pull/8462), [#8463](https://github.com/flwrlabs/flower/pull/8463), [#8464](https://github.com/flwrlabs/flower/pull/8464), [#8467](https://github.com/flwrlabs/flower/pull/8467), [#8468](https://github.com/flwrlabs/flower/pull/8468))

  SuperLink now serves the Fleet and Control APIs over HTTP only. Their legacy gRPC services and the optional gRPC health service have been removed, remaining compatibility gRPC code lives under `flwr.compat`, and deprecated transport options no longer configure active services.

- **General improvements** ([#8410](https://github.com/flwrlabs/flower/pull/8410), [#8413](https://github.com/flwrlabs/flower/pull/8413), [#8421](https://github.com/flwrlabs/flower/pull/8421), [#8422](https://github.com/flwrlabs/flower/pull/8422), [#8436](https://github.com/flwrlabs/flower/pull/8436), [#8447](https://github.com/flwrlabs/flower/pull/8447), [#8455](https://github.com/flwrlabs/flower/pull/8455), [#8465](https://github.com/flwrlabs/flower/pull/8465), [#8466](https://github.com/flwrlabs/flower/pull/8466), [#8470](https://github.com/flwrlabs/flower/pull/8470), [#8471](https://github.com/flwrlabs/flower/pull/8471), [#8472](https://github.com/flwrlabs/flower/pull/8472))

  As always, many parts of the Flower framework and quality infrastructure were improved and updated.

### Incompatible changes

- **Handle unavailable nodes without waiting for round timeouts** ([#8426](https://github.com/flwrlabs/flower/pull/8426))

  When a SuperNode goes offline, `Strategy.start()` now generates an error reply instead of waiting until the round timeout. Replies received before the node becomes unavailable are preserved, while nodes that remain available continue to use the configured timeout.
