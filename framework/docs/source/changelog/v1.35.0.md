### What's new?

- **Use OpenAI SDK requests and control AgentApp events** ([#7971](https://github.com/flwrlabs/flower/pull/7971), [#7976](https://github.com/flwrlabs/flower/pull/7976), [#7977](https://github.com/flwrlabs/flower/pull/7977), [#7979](https://github.com/flwrlabs/flower/pull/7979), [#7983](https://github.com/flwrlabs/flower/pull/7983), [#7985](https://github.com/flwrlabs/flower/pull/7985))

  AgentApps can now make non-streaming or SSE-streamed Open Responses requests through `POST /v1/runtime/responses` with the OpenAI SDK. Source-task filtering and context locking keep parallel model calls isolated, while `agent.events.emit(...)` lets apps selectively publish model events that remain private by default.

- **Continue conversations and choose federations in `flwr chat`** ([#7836](https://github.com/flwrlabs/flower/pull/7836), [#7933](https://github.com/flwrlabs/flower/pull/7933), [#7964](https://github.com/flwrlabs/flower/pull/7964), [#7965](https://github.com/flwrlabs/flower/pull/7965), [#7972](https://github.com/flwrlabs/flower/pull/7972), [#7992](https://github.com/flwrlabs/flower/pull/7992))

  Use `/history` to browse and continue AgentApp conversations, with run-series filtering separating agent history from other runs. `flwr chat` now renders assistant responses as Markdown, lets users select a federation, and starts new conversations in their personal federation by default.

- **Build AgentApps with a CLI template and expanded guides** ([#7903](https://github.com/flwrlabs/flower/pull/7903), [#7906](https://github.com/flwrlabs/flower/pull/7906), [#7925](https://github.com/flwrlabs/flower/pull/7925), [#7927](https://github.com/flwrlabs/flower/pull/7927), [#7947](https://github.com/flwrlabs/flower/pull/7947), [#7961](https://github.com/flwrlabs/flower/pull/7961))

  Run `flwr new agent` to create a minimal AgentApp, then follow refreshed tutorials covering project setup, runtime concepts, model-directed tool use, connectors, and automations. One-time automations are now created without an invalid `fixed_interval`.

- **Run the Runtime API over HTTP** ([#7890](https://github.com/flwrlabs/flower/pull/7890), [#7907](https://github.com/flwrlabs/flower/pull/7907), [#7913](https://github.com/flwrlabs/flower/pull/7913), [#7923](https://github.com/flwrlabs/flower/pull/7923), [#7924](https://github.com/flwrlabs/flower/pull/7924), [#7936](https://github.com/flwrlabs/flower/pull/7936), [#7954](https://github.com/flwrlabs/flower/pull/7954), [#7955](https://github.com/flwrlabs/flower/pull/7955), [#7956](https://github.com/flwrlabs/flower/pull/7956), [#7959](https://github.com/flwrlabs/flower/pull/7959), [#7960](https://github.com/flwrlabs/flower/pull/7960), [#7963](https://github.com/flwrlabs/flower/pull/7963))

  The Runtime API now uses HTTP instead of gRPC across SuperLink, SuperNode, SuperExec, and `flwr-*` processes, with retry handling, shared clients, version compatibility checks, and consistent JSON errors. Obsolete Runtime gRPC components are removed, while the existing Fleet and Control gRPC paths remain unchanged.

- **Track fixed-clipping privacy loss (research preview)** ([#7934](https://github.com/flwrlabs/flower/pull/7934), [#7958](https://github.com/flwrlabs/flower/pull/7958))

  Client-side and server-side fixed-clipping strategies can now use an optional privacy accountant to report cumulative privacy loss and stop before the next release would exceed `max_epsilon`. The accounted path currently requires no-amplification accounting and uniform `FedAvg` aggregation.

- **Manage Flower Apps in federations** ([#7932](https://github.com/flwrlabs/flower/pull/7932), [#7948](https://github.com/flwrlabs/flower/pull/7948), [#7951](https://github.com/flwrlabs/flower/pull/7951), [#7962](https://github.com/flwrlabs/flower/pull/7962))

  Flower now provides Control API and state support for adding and removing FAB-backed apps from federations. App listings always include `flwr-agent`, completing the initial federation app-management path.

- **Build valid FABs with clearer errors** ([#7950](https://github.com/flwrlabs/flower/pull/7950), [#7969](https://github.com/flwrlabs/flower/pull/7969))

  FAB creation now validates the complete Flower App configuration for every caller, including Hub publishing. `flwr build`, `flwr run`, and `flwr app publish` also explain path-depth failures and ignore `.venv` contents before enforcing the limit.

- **Integrate with run startup and shutdown** ([#7938](https://github.com/flwrlabs/flower/pull/7938), [#7970](https://github.com/flwrlabs/flower/pull/7970))

  Extensions can observe a persisted run through the best-effort `on_run_started` hook without affecting a successful start. Exit handlers can also opt to complete critical cleanup before the force-shutdown timer begins while preserving the existing default phase.

- **General improvements** ([#7882](https://github.com/flwrlabs/flower/pull/7882), [#7935](https://github.com/flwrlabs/flower/pull/7935), [#7937](https://github.com/flwrlabs/flower/pull/7937), [#7939](https://github.com/flwrlabs/flower/pull/7939), [#7940](https://github.com/flwrlabs/flower/pull/7940), [#7942](https://github.com/flwrlabs/flower/pull/7942), [#7943](https://github.com/flwrlabs/flower/pull/7943), [#7949](https://github.com/flwrlabs/flower/pull/7949), [#7952](https://github.com/flwrlabs/flower/pull/7952), [#7957](https://github.com/flwrlabs/flower/pull/7957), [#7968](https://github.com/flwrlabs/flower/pull/7968), [#7981](https://github.com/flwrlabs/flower/pull/7981))

  As always, many parts of the Flower framework and quality infrastructure were improved and updated.
